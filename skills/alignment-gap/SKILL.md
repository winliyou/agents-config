# 对齐鸿沟：双方信息没对上时，先对齐事实

> 同一个问题在用户与验证方之间反复对不上时，根因通常不是某一类 bug，而是双方各自拿着一份不完整的事实做判断。本文只保留可迁移的协作模式，不绑定具体项目、设备或端。

## 0. 一句话

当用户和你对同一问题得出相反结论时，第一假设是「双方掌握的事实不同」，而不是「对方判断错了」或「自己的代码一定错了」。

## 1. 这是一类协作失效，不是某一类 bug

同一句「我这边没问题」，背后可能是六种信息缺口之一：

| 分歧类型 | 双方各自看到什么 | 典型表现 |
|---|---|---|
| 观察条件 | 同一操作、不同环境产生不同结果 | 只在大屏/特定缩放/特定设备/特定网络复现 |
| 版本与状态 | 一方跑旧代码、旧缓存，或另一份数据/账号 | 「我修好了」但对方还是旧表现 |
| 操作路径 | 双方做的是不同路径或不同前置状态 | 「按你说的点了，就是不行」 |
| 术语与观察粒度 | 「打开卡片」「没反应」指的不是同一件事 | 描述对不上、答非所问 |
| 验收标准 | 对「修好」的定义不同 | 功能好了，但对方期望的是另一种表现 |
| 需求理解 | 用户要的 ≠ agent 理解的 | 做出来的不是对方想要的 |

环境不同导致的**复现鸿沟**只是「观察条件」这一类里最常见的一种，不要把它当成全部。

判断方法：问自己「对方看到的那份事实，我看到了吗？」没看到就属于信息缺口，先补事实，不要先下结论。

## 2. 共享事实集（下结论前双方都得有）

- 操作：在什么条件下、做什么操作、期望看到什么；
- 现象：实际看到什么（粒度到可观察的最小步骤或数值，不要形容词）；
- 条件：环境参数、版本、状态、复现概率；
- 验收：怎么算修好、由谁确认、在哪个场景确认。

任何一条缺失时，双方的结论都只是「私人事实」，不能当共识。**先把它变成共享事实，再讨论对错。**

## 3. 硬规则

- **连续两轮「我这边验证通过 + 用户仍反馈」后，禁止再直接改代码继续猜**，必须转成「对齐共享事实 + 取证」。
- 每轮结论必须写出你的共享事实（环境/版本/操作/证据），不能只说「已修复」。
- 用户确认前，措辞上限是「我按某条件验证通过，需要你在你的场景确认」；不得宣布问题已解决。
- 不确定双方说的是不是同一个现象时，先复述确认，再动手。

## 4. 对齐动作（成本从低到高）

1. **对齐验收口径**：一句话说清「什么条件、什么操作、看到什么算好」。
2. **补共享事实**：要能一锤定音的最小证据（录屏/截图/日志/版本号/复现概率），不要一次问一堆。
3. **参数化复现**（「观察条件」分歧的专用手段）：把验证条件当变量，至少跑「对方给出的精确条件 + 边界值」；能算先算（用坐标或量级推算哪一档会失效）；一次只改一个变量做二分；警惕自动化工具的默认环境不等于真实环境。
4. **远程取证**：让用户在对方环境跑一次最小诊断（开关/命令/脚本），把对方环境变成可读证据。
5. **收敛**：整理「我的事实 / 对方的事实 / 差异 / 已排除项」，提具体二选一问题；实在对不齐就如实说明需要什么信息，而不是假装修复。

## 5. 术语与观察粒度的对齐技巧

- 把对方的描述翻译成「可观察的动作 + 结果」再复述确认（「你说的打开卡片，是点了没反应，还是打开了内容没显示？」）。
- 给选项而不是开放问题；能二选一就不要让人描述。
- 对方说「还是不行」时，先问「和上次相比哪里不一样」——变化点比当前状态更好定位。

## 6. 验收与需求分歧

- 动手前写下期望行为（几句话），让对方确认；有两种理解时给二选一。
- 「实现正确」不等于「对方想要」：验收标准要覆盖行为与体验（反馈、动效、可感知结果）。
- 需求类分歧同样先对齐再动手——先做对的事，再把事做对。

## 7. 反模式

- 用「我这边没问题，你再试试 / 清下缓存 / 是不是你环境的问题」结案；
- 反复在同一条件下验证，并把它当成证据；
- 只验证默认条件、默认设备、默认账号；
- 修完不写验证条件，让对方一次次替你验证；
- 把对方反馈当噪音，或把对方当免费测试员；
- 一边说「修好了」一边让对方重新描述同一个问题。

## 8. 修好之后（防复发）

- 把这次对齐出的共享事实（条件/版本/验收）写进回归矩阵或验收清单，作为必须覆盖的一档；
- 若暴露的是系统性盲区，把盲区写进项目侧 QA/巡检清单；处理模式留在本 skill。

## 9. 最小提问模板

> 我这边在「条件」下验证通过，但你的现象说明我们至少有一处信息不同。为了不让你反复试，我需要：
> ① 复现时的条件（环境/设备/版本/账号）；
> ② 一段能看清操作和结果的录屏或截图；
> ③ 是每次必现，还是特定条件下才出现？大概什么条件；
> ④ 你说的「某现象」具体指哪一步、看到什么。
