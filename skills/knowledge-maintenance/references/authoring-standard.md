# 文档写法规范（AGENTS.md / skill）

## 一句话原则
文档是**当前状态的快照**，不是操作日志。读者只需要知道「现在是什么、该怎么做、怎么验证」，
不关心它是什么时候、因为谁、从什么状态变成现在的——那些属于 git 历史。

## 禁止写（skill-lint 会拦）
- 日期 / 时间：20xx-xx-xx、20xx-xx 实测、15:02 等（真实文件名、协议常量除外）
- 归属与事件：用户要求、用户确认、我上次、本次、上一轮、后来、当时、曾经
- 变更史：版本历史、更新记录、变更记录、时间线、里程碑、R1/R2、重构前/修复前/修复后、旧文/旧版/已作废/已废弃
- 事故叙事：事故复盘、踩坑记录、排查流水账（「当时以为是 X，后来发现是 Y」）
- 「本次改了什么」的逐条清单（commit message 才是变更记录）

## 应该写
- 当前有效的规则/约束（祈使句：必须 / 禁止 / 优先）
- 命令与参数、路径、配置字段（可复制、可执行）
- 判据：怎么判断成功/失败、怎么区分真因
- 陷阱：写成「陷阱 / 限制：……」的规则，不写成故事
- 权威源指针：实现/契约以代码、spec 为准的地方直接指过去

## 更新既有文档的流程
1. 先查同类内容是否已存在（同一事实只能有一处）
2. **直接替换旧断言**：删掉旧说法、写新说法；不要追加「更新于……」
3. 新旧冲突先证伪：用命令核实，保留被验证的一方
4. 同一事实只留一处，其余改指针
5. 写完跑 skill-lint（--all 覆盖项目级与项目 AGENTS.md），ERROR 必须清零
6. 文档里不写变更说明

## skill 结构模板
见本 skill 的 templates/SKILL.md。frontmatter 必须 name + description
（description ≤ 500 字符，且包含触发词）；正文建议顺序：

- 何时用（触发场景）
- 规则 / 做法（祈使句）
- 命令 / 路径 / 参数（可执行）
- 验证方式（怎么证明有效）
- 陷阱 / 限制（规则式表述）
- 权威源（代码/spec 指针）

## AGENTS.md 写法
- 只放「每次都需要」的红线与一句话约束；长流程/细节放 skill
- 不堆历史、案例、事故记录；案例放 skill 的陷阱小节
- 新约定必须可执行：写命令/判据，不写空泛原则
- 归属：跨项目通用 → 用户级 AGENTS/skill；项目专属 → 项目 AGENTS/skill

## 反例 → 正例
反例：某次按用户要求把 X 改成 Y，修复后 Z 正常。
正例：必须使用 Y；判据：执行 Z 命令返回 0。

反例：之前用 A，后来发现 A 有 bug，现已改为 B，A 已作废。
正例：使用 B；A 在 C 场景会失败，禁止使用。

反例：## 变更记录 — 本次新增了 D 校验。
正例：校验规则：D 必须通过；验证命令：<命令>。

## 检查与闸门
- skill-lint：日期、变更记录/更新日志/时间线/踩坑记录类章节 → ERROR；变更史短语 → WARN
- skill-lint --all：附带检查 ~/work 下项目 AGENTS.md 与项目级 skill
- ~/.agents 仓库的 pre-commit 已启用（core.hooksPath=.githooks）：有 ERROR 直接拒收提交；新机或重新 clone 后执行 git -C ~/.agents config core.hooksPath .githooks 启用
- 项目仓库若要同样闸门，可在其 pre-commit 中调用 skill-lint（按项目需要）
- 新建 skill 可用 skill-new 生成骨架：skill-new <name> [skills 目录]
