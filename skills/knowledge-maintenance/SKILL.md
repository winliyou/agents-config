# 知识库保鲜（Knowledge Maintenance）

沉淀不是一次性写入，而是**持续维护**：写进去的每条事实都有保质期，过期后会主动误导后续 AI。
本 skill 定义「写什么、写到哪、什么时候回来改、怎么发现已经错了」。

## 核心认知：沉淀会腐烂

知识的腐烂速度由**事实类型**决定，不是由写得是否认真决定：

| 事实类型 | 举例 | 腐烂速度 | 对策 |
|---|---|---|---|
| 版本号 | `gh 2.102.0`、`pnpm@12.4.2` | 快（月级） | **不写死数字**，写「以 `cmd --version` 为准」 |
| 路径 / 配置文件名 | 某工具的安装路径、某个配置文件的位置 | 中（工具升级会变） | 写之前 `ls` 核实；写后给出复核命令 |
| 命令与参数 | `hvigor --mode module assembleHap` | 中（工具大版本会变） | 附「口径命令」，让读者能自证 |
| 数字型断言 | 「4 类 48 例测试」「桌面 20 页」 | 快（每次加测试就错） | **不写数字**，或写「用 <命令> 现取」 |
| 架构 / 契约 | 接口前缀、状态机、分层 | 慢（改架构才变） | 标注「唯一权威源」指向 spec/代码 |
| 方法论 / 踩坑机理 | 「CDP 断连有三种真因」 | 很慢 | 最值得沉淀，放心写 |

**推论**：沉淀时优先写「机理与方法」，把「具体数值」压缩成「取数命令」。
一条好的沉淀是「怎么验证」，不是「我上次看到的值」。

## 写什么（触发条件，主动做，不等用户开口）

会话结束前，以下四类必须提炼，否则会被对话冲掉：

1. **踩坑与排障结论**：报错原文 → 误导性表象 → 真正根因 → 验证过的解法。
   缺任何一环都不算完成；只写「注意 xxx」等于没写。
2. **环境事实**：路径、版本、端口、服务拓扑、凭据归档位置。写时**必须给出可复核的验证方式（命令/取数口径）**。
3. **可复用流程**：多步、有顺序、需要判断分支的操作（写进主题 skill，不写成清单）。
4. **被纠正的做法**：用户指出做法不对时，把「为什么错 + 正确做法」写成规则，防止再犯。

**不写**：只对本次会话成立的临时状态、能从代码直接读出的内容、空泛原则（「要注意质量」）。

## 写到哪（归属判定）

| 内容性质 | 落点 |
|---|---|
| 每次都要遵守的**红线**（一句话） | 用户级 `~/.agents/AGENTS.md` |
| 成体系的长流程、工具链规程、环境事实 | 用户级 skill `~/.agents/skills/` |
| 只在某项目成立的约定（路径/命令/端口/账号） | 该项目根目录的 AGENTS.md，或该项目的 skills 目录 |

**硬判定口径**：用户级 skill 里**不得出现具体项目的名字、路径、命令、账号、端口**。
只要一条经验只在该项目里成立，就必须写到项目侧；用户级只留可迁移的通用模式。

沉淀前**先查是否已有同类 skill**，优先补充既有 skill。同类知识散落多处即视为漂移。

## 不维护什么（第三方 skill 不在范围内）

**第三方 skill 不归我们维护，不用管。** 它们来自外部仓库或上游发布包，本地改了也会被覆盖：

| 判定来源 | 说明 |
|---|---|
| `~/.agents/.third-party-skills` | 显式清单（自动识别不出来时手工登记） |
| `~/.agents/.skill-lock.json` | 由 skills CLI 锁定的来源与 hash（如 `agent-browser`、`find-skills`） |
| frontmatter 特征 | 带 `metadata.author` / `license:` / `argument-hint:` 的上游格式 |

对本范围的规则：

- **不要求**它们正文可复核、不追着修里面失效的路径/命令——那不是我们的债。
- `skill-lint` 默认跳过它们，只输出 `SKIP`；需要看时加 `--with-third-party`。
- **绝对不要往第三方 skill 里追加本地内容**（上游更新会静默冲掉，本地规程会丢）——这类内容一律写进自建 skill。
- 第三方 skill 缺能力时，**写一个自建的补充 skill 指向它**，而不是改它。

### 更新走官方 CLI，不要手工编辑

```bash
npx skills list -g              # 看 Source：非 local 才有上游可更新
npx skills update -g -y         # 更新全部全局 skill
npx skills update <name> -g -y  # 只更新指定 skill
```

**`update` 只比对远端版本，检测不到本地漂移**：文件被手工改过、但远端没发新版时，
它会报「all up to date」却留着本地改动。要拿回纯净上游版必须重装：
`npx skills remove -g -s <name> -y` → `npx skills add <owner/repo> -g -y -s <name> --copy`。

来源显示为 `local` 的是**自建 skill**：没有上游、不该去更新，本来就归本仓库维护（数量现取：`ls ~/.agents/skills` 减去 `~/.agents/.third-party-skills`）。
第三方 skill 都已能被 CLI 跟踪（`vercel-labs/*` 与 `nextlevelbuilder/ui-ux-pro-max-skill`），
`npx skills update -g -y` 直接生效；详见 `~/.agents/README.md`「第三方 skill」一节。

## 冲突时怎么办（不要两份并存）

发现结论与新事实矛盾时：

1. **先证伪，再采信**：不要因为新结论「看起来更对」就直接改。用可执行命令核实一次。
2. 保留**被验证的一方**，另一方删除或改成指针。
3. 不保留失效记录；确需交代背景时只留现行结论与可复核验证方式，不得让旧结论读起来仍像现行规则。

沿用别人（或自己）写下的环境结论前，**先证伪一次**——
沿用陈旧的「推入式页面白屏、必须真机」类结论会掩盖真 bug，直到端上截图才暴露。

## 何时复核（过期触发器）

不要等"定期"，用**事件触发**，成本低且必然发生：

| 触发器 | 复核范围 |
|---|---|
| 工具/依赖升级（hvigor、DevEco、Go、pnpm、DSH 宿主…） | 所有写了该工具版本、路径、参数的 skill |
| 项目改架构 / 换目录 / 改构建脚本 | 该项目 AGENTS.md 与全部 skill |
| 新增或修改测试 | 所有写了测试数量的地方 |
| 结论被证伪（排查中发现旧说法错了） | **当场改**，不要留到下次 |
| 会话结束前 | 本次新踩的坑、新查的环境事实 |
| 用户说「沉淀」「更新 skill」「这条不对」 | 相关 skill 全量复核 |

**周期性体检**（建议每月一次，或大改后）跑 `skill-lint`（见下）。

## 怎么发现已经错了（skill-lint）

`~/.agents/bin/skill-lint` 把**能机器判定**的腐烂类型一次扫出来：

```bash
skill-lint                    # 用户级 ~/.agents/skills
skill-lint --all              # 用户级 + ~/work 下全部项目级
skill-lint --json             # 机器可读
skill-lint --with-third-party # 连第三方 skill 一起查（默认跳过）
skill-lint <某个 skills 目录>
```

检测项：

| 检测 | 为什么重要 |
|---|---|
| frontmatter 缺 `name`/`description` | DSH **静默忽略**该 skill，等于它消失了 |
| frontmatter 值含未加引号的 `: ` | YAML 解析失败，同样被静默忽略（`description: 用于 websites: 导航` 就中招）——加引号即可 |
| `description` > 500 字符 | DSH 目录渲染截断成 `...`，尾部触发词失效 |
| 正文引用的本机路径不存在 | 最常见的腐烂：路径搬了/工具卸载了 |
| 引用不存在的 skill 名 | 改名后残留的悬空指针 |
| 孤儿 skill（项目内无任何 Markdown 提及） | AI 很难发现它，沉淀等于白写 |
| 正文出现日期标注 | 文档应写现状，日期属于 git 历史（ERROR） |
| 变更记录/更新日志/时间线/踩坑记录类章节 | 典型的流水账结构，历史交给 git（ERROR） |
| 变更史式表述（已作废/修复前/旧文…） | 叙事化旧结论，应改写成现状（WARN） |

输出里的 `SKIP` 表示第三方 skill 已按规则跳过——**这是预期行为，不用处理**。

**判定口径**：ERROR 必须修（skill 已失效、不可发现，或出现日期/变更史类内容）；WARN 逐条判断——
「路径不存在」有时是**正确描述**（在说明某文件本机未配置），脚本已对含「不存在/未配置」的行做豁免，其余需人工确认。

## 修完要验证（红线）

改完 skill / AGENTS.md 后：

```bash
skill-lint          # 用户级 skill + 全局 AGENTS.md
skill-lint --all    # 再加 ~/work 项目级 skill 与项目 AGENTS.md
```

**日期、变更记录/更新日志/时间线/踩坑记录类章节都是 ERROR**；`~/.agents` 仓库的提交由 pre-commit 强制检查。

引用过的命令，**实际跑一次**确认仍然有效；改路径的，`ls` 确认目标存在。
「改完了」不等于「改对了」——未验证的修改本身就是新的腐烂源。

## 批量改动的安全顺序

一次性迁移/恢复多个文件时，顺序错了会真丢数据（实测丢失过 14 个已跟踪文件的改动）：

1. **先备份，且要验证备份完整，再动原文件**。
   ```bash
   cat a.txt b.txt > all.txt && tar -cf back.tar -T all.txt
   tar -tf back.tar | wc -l        # 条数必须等于清单行数，否则备份是残的
   ```
   **BSD tar（macOS 自带）对多个 `-T` 只认最后一个**，前面的清单被静默忽略——被忽略的
   `-T` 清单里的文件全部没进包，后续 `git checkout -- .` 会把它们还原到 HEAD，改动全丢。
2. **破坏性命令必须在改动已安全落盘之后**：`git checkout -- .` / `git clean -fd` 只能放在
   「已提交到分支」或「已复制出仓库并经校验」之后，不能先还原再想办法备份。
3. 走到 worktree 流程时正确顺序是：**建 worktree → 复制改动进去 → 在 worktree 提交 → 还原主树 → ff-only 合并**。
   先还原再提交等于把退路提前拆掉。

## 沉淀质量要求

- 写**可验证的事实与命令**，不写空泛原则。
- 每条环境结论给出**可复核的验证方式（命令/取数口径）**，不写日期。
- 数字型断言一律附**取数命令**，让读者能自证，而不是信任数字。
- 与既有内容冲突时先核实事实再改，不要并存两种说法。
- 优先写「怎么判断」，而不是「我上次看到什么」。

## 写法规范（防流水账，新建/修改文档前先读）

- 文档是**当前状态快照**，不是操作日志：禁止日期、变更史、用户/事件归属、事故复盘式叙事。
- 更新既有文档：**直接替换旧断言**，不追加「更新于……」；同一事实只留一处。
- 新 skill 用本 skill 的 `templates/SKILL.md` 骨架，或 `skill-new <name>` 生成目录。
- 完整规范、反例与更新流程见 `references/authoring-standard.md`。
- 写完跑 `skill-lint`：日期与变更史类章节是 **ERROR**；`~/.agents` 仓库的 pre-commit 会直接拒收。

## 沉淀后的自检（每次新增或大改 skill 后跑）

`skill-lint` 覆盖能机器判定的部分；下面三条是它**查不出**的语义问题，需人工判断：

```bash
# ① 项目专有内容不得出现在用户级 skill（项目名/路径/账号/端口）
#    括注里的名字是模式示例，按本机实际仓库名替换；本行会命中自己，属预期
grep -rniE "\b(<项目a>|<项目b>|<项目c>|<项目d>|/Users/[a-z]+|uitest_)" ~/.agents/skills/*/SKILL.md

# ② 项目侧 AGENTS.md 的 skill 索引与实际目录一致（漏索引 = skill 很难被发现）
cd <项目根> && comm -3 \
  <(grep -oE '^\| `[a-z-]+`' AGENTS.md | tr -d '|` ' | sort) \
  <(ls .agents/skills | sort)
```

判定与修复：

- ① 有命中 → **项目事实搬到项目侧**（项目 AGENTS.md 或该项目的 skills 目录），机器事实搬 `local-environment`；
  用户级只留可迁移的通用模式（工具路径如 `~/.hvigor` 属工具事实，可保留）。
- ② 有差异 → 补索引条目。**别指望系统自动发现能兜底**：目录确实会被挂载，但 AI 很难主动想到加载一个没被任何文档提到的 skill。
- **同一事实在两处出现即视为漂移**：保留一处，另一处改成指针（「见 `xxx` skill」）。
- 结论互相矛盾时：**保留被验证的一方 + 给出其复核方式**，不要两份并存。

> 自检清单不得写进第三方 skill：第三方 skill 由 `.skill-lock.json` 锁定，
> 更新会覆盖手改内容，本地规程会静默丢失。本地沉淀一律写进自建 skill。
